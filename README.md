# Візуалізація роботи блокчейну

Курсова робота. Ядро на **Rust**, інтерфейс відображає **Chromium** у режимі вікна застосунку (`--app`). Інтерфейс написано на чистих HTML, CSS і JavaScript, без TypeScript, фреймворків і збірника.

У центрі полотна — ланцюг блоків. Зв'язки між ними повільно дрейфують хвилею, схожою на синусоїду, але з періодом, що постійно змінюється. Праворуч — невелика панель керування.

## Запуск

Потрібні Rust (edition 2024) і Chromium. На Arch Linux: `sudo pacman -S chromium`.

```bash
cargo run --release
```

Програма запускає локальний сервер на `127.0.0.1` з випадковим портом і відкриває вікно Chromium. Коли вікно закривається, програма завершується.

| Параметр | Що робить |
|---|---|
| `--no-browser` | тільки сервер; адресу відкрийте в будь-якому браузері |
| `--port 7878` | фіксований порт замість випадкового |
| `--data шлях/chain.txt` | інший файл для збереження ланцюга |
| `--no-save` | ланцюг лише в пам'яті, без збереження |
| `CHROMIUM_PATH=/шлях/до/браузера` | інший Chromium-сумісний браузер (Chrome, Brave, Edge) |

### Збереження ланцюга

Як і вузол криптовалюти, програма зберігає ланцюг на диск після кожної зміни і відновлює його при наступному запуску. Файл лежить у `~/.local/share/kursova_rust/chain.txt` (на Windows — `%APPDATA%\kursova_rust\chain.txt`). Це звичайний текстовий файл: один рядок на блок. Після завантаження Rust перевіряє весь ланцюг. Якщо змінити дані блоку у файлі вручну, інтерфейс покаже, який блок порушено. Пошкоджений файл відкладається як `chain.bad`, і створюється новий ланцюг. «Скинути» повертає початкові блоки й перезаписує файл.

Тести ядра:

```bash
cargo test
```

## Що можна робити

- **Майнити** новий блок: ввести дані → «Майнити». Rust перебирає nonce, доки SHA-256 хеш не почнеться з потрібної кількості нулів.
- **Складність** (1–5) діє на нові та перемайнені блоки.
- **Вибрати блок** кліком: у панелі з'являться час, nonce, хеш, `prevHash` і дані.
- **Підробити** — змінити дані без перерахунку хешу. Блок стає червоним, а всі наступні — тьмяними (ланцюгу після розриву довіряти не можна).
- **Перемайнити** блок — хеш знову правильний, але тепер розривається зв'язок із наступним блоком (червона пунктирна лінія). «Перемайнити до кінця» відновлює весь ланцюг — так видно, чому підробка в реальному блокчейні дорога.
- **Покрокове пояснення** з'являється після «Майнити»: вміст блоку → підбір nonce → знайдений хеш → блок у ланцюгу. Кроки йдуть самі, але їх можна гортати кнопками «Назад» / «Далі», крапками або стрілками ← →. Картка закривається кнопкою «Зрозуміло», × або `Esc`. Для будь-якого наявного блоку є кнопка «Як створено цей блок».
- **Панель** можна розтягнути вниз за ручку в нижньому краї; подвійний клік по ручці повертає автоматичну висоту.
- **Перевірити** — імпульс біжить ланцюгом від генезису, кожен блок спалахує зеленим або червоним.
- **Посилання автора**: наведіть мишку на лівий верхній кут і натисніть стрілку. Адреси задаються у `frontend/js/links.js`.
- Полотно: колесо — масштаб, перетягування — рух полотна або ноди, подвійний клік / `F` — вмістити граф, пробіл — пауза дрейфу, `Esc` — зняти вибір.

## Сайт курсової

Тека `site/` — окремий статичний сайт про історію блокчейну в коричнево-золотому стилі (палітра Brown `#603E1E`, Pale Gold `#F1D9A8`, Glowing Gold `#FFC34D`, промені світла згори): `index.html`, `style.css`, `script.js`. Збирати нічого не треба: відкрийте `site/index.html` у браузері або викладіть теку на GitHub Pages чи будь-який хостинг.

- Кожен розділ історії оформлено як блок; браузер майнить його (SHA-256 через WebCrypto, складність 3), а «попередній хеш» посилається на розділ вище.
- Зліва — хронологія з хвилястими зв'язками, як на полотні програми; золота точка рухається ланцюгом під час гортання.
- Світла й темна теми: за налаштуваннями системи або кнопкою в правому верхньому куті (вибір запам'ятовується).

- Сторінка `author.html` «Про автора» (кнопка внизу хронології): посилання на соцмережі задаються в `site/links.js`, а ім'я — там само в полі `name`.

Після публікації вставте адресу сайту в `frontend/js/links.js` (картка «Сайт курсової»).

## Архітектура

```text
src/
  main.rs         точка входу: сервер + запуск вікна Chromium
  sha256.rs       власна реалізація SHA-256 (FIPS 180-4) з тестовими векторами
  blockchain.rs   Block, Blockchain: майнінг (proof-of-work), підробка, перевірка
  json.rs         серіалізація стану в JSON
  server.rs       HTTP/1.1-сервер на std::net, API та вбудовані файли інтерфейсу
  storage.rs      збереження ланцюга на диск і відновлення при запуску
  browser.rs      пошук і запуск Chromium (--app, окремий профіль)
frontend/
  index.html      розмітка: полотно + панель
  style.css       мінімалістичне оформлення, світла й темна теми
  js/main.js      панель керування, журнал, зв'язок з API
  js/graph.js     Canvas 2D: ноди, хвилясті зв'язки, камера, анімації
  js/api.js       виклики HTTP API
  js/explainer.js покрокове пояснення створення блоку
  js/log.js       журнал подій
```

Проєкт не має жодної зовнішньої залежності: криптографія, HTTP і JSON написані на стандартній бібліотеці Rust. Файли `frontend/` вбудовуються в бінарник через `include_str!`, тож після змін інтерфейсу достатньо перезапустити `cargo run`.

### Блок і хеш

```text
hash = SHA-256( index | timestamp | prevHash | difficulty | nonce | data )
```

Під час перевірки для кожного блоку Rust визначає:

- `hashOk` — збережений хеш дорівнює перерахованому з поточних даних;
- `linkOk` — `prevHash` дорівнює хешу попереднього блоку;
- `powOk` — хеш починається з `difficulty` нулів.

Перший блок, що не пройшов перевірку, — `firstInvalid`. Блоки після нього інтерфейс показує як недовірені.

### HTTP API

Кожна відповідь — повний стан ланцюга з результатами перевірки.

| Запит | Дія |
|---|---|
| `GET /api/chain` | поточний стан |
| `POST /api/blocks` (тіло — дані) | замайнити новий блок |
| `POST /api/blocks/{i}/data` (тіло — дані) | підробити дані блоку |
| `POST /api/blocks/{i}/mine?cascade=0\|1` | перемайнити блок (або до кінця) |
| `POST /api/difficulty?value=n` | змінити складність |
| `POST /api/reset` | повернути початковий ланцюг |

### Дрейф зв'язків

Кожна точка зв'язку `u ∈ [0, 1]` зміщується перпендикулярно до прямої між нодами:

```text
off(u, t) = sin(πu) · A(t) · [ sin(2π·k(t)·u − φ(t)) + 0.3 · sin(2π·1.7k(t)·u + 0.6φ(t) + s) ]
φ(t) = ∫ ω(t) dt,   ω(t) = ω₀ · (1 + 0.5·sin(0.17t + s₁) + 0.28·sin(0.43t + s₂))
```

Фаза накопичується зі змінною швидкістю `ω(t)`, а амплітуда `A(t)` і хвильове число `k(t)` теж повільно змінюються. Тому рух схожий на синусоїду, але не повторюється з одним і тим самим періодом. Множник `sin(πu)` тримає кінці зв'язку на нодах. Самі ноди дрейфують на кілька пікселів сумою синусоїд із несумірними частотами. Кожен зв'язок і кожна нода мають власні фази, тому вони рухаються не синхронно.
